# بروتوكول Meta المؤقت — تصدير يدوي لحد ما حجب الـ API يتفك
اتفعّل 2026-11-19. الهدف: بيانات أداء حقيقية تدخل السستم من أول يوم تيست، من غير انتظار حل الحجب.

## دور المالك (5 دقايق، مرتين أسبوعياً أثناء التيست — أو عند الطلب)
من Ads Manager: اختار آخر 3 أيام → تصدير (Export) بجدول الحملات، بالأعمدة دي:
Campaign name / Ad set name / Ad name / Amount spent / Impressions / Reach / CTR (link) / Link clicks / Landing page views / Purchases / Cost per purchase / CPM / Frequency / Day.
والتصدير يتحط في أي قناة من دول: (أ) يتلصق في السستم (مدخلات المالك)، (ب) يتبعت هنا في الشات، (ج) يترفع ملف CSV في الشات.

## دور السستم (تلقائي — كرون zyra-meta-manual-intake يومياً 09:30 + عند أي لصق جديد)
1. يكتشف تصديراً جديداً لم يُعالج ويقرأه.
2. يبني/يحدّث سجلات الحملات في «التسويق» بالأرقام الفعلية.
3. يسجل لقطة مالية بالأداء (صرف/طلبات/CPP فعلي).
4. يشغّل منطق Task D على كل حملة ويجهّز قرارات Kill/Keep/Scale كمسودات في صندوق القرارات — لا تنفيذ إلا باعتماد المالك.
5. يحدّث سجل المعايرة: CPP الفعلي مقابل توقعات المحاكي (SIM-1) وتوقع الـ CPM.
6. يلخص للمالك في الموجز التالي: اتعالج تصدير بتاريخ كذا، أهم 3 إشارات.

## قواعد
- أرقام التصدير هي الحقيقة الوحيدة للأداء لحد ربط الـ API — ولا رقم أداء يُكتب في السستم من أي مصدر تاني.
- التصدير بيانات أداء فقط؛ مفيش أي تعديل على الحساب الإعلاني من البروتوكول ده.
- أول ما كرون إعادة محاولة الـ API ينجح، البروتوكول ده يقف تلقائياً ويتحول لمراجعة تطابق أسبوعية.
