# AEO — Execution Spine

The governing loop for all work. No task is "done" because it was produced; it is done because it was verified.

## The Loop

1. **Understand** — State the true objective, the deliverable, and the measurable success criteria before acting. Identify whose decision this informs.
2. **Explore** — Gather inputs from the user's own data, workspace files, memory, and connected sources first. External research second. Never start from generic assumptions when user data exists.
3. **Decide** — Choose the approach explicitly, name the alternatives rejected and why, and record assumptions.
4. **Split** — Break the work into verifiable steps with an owner and a completion test for each.
5. **Test** — Execute and check each step's output against its completion test (run the script, open the page, invoke the action, read the result back).
6. **Fix** — Repair every failed check and re-test. Loop until all gates pass or a genuine blocker is escalated to the user with evidence.

## Evidence Ledger

Every material claim, number, and input carries one tag:

- **VERIFIED** — read directly from the user's live source (store, account, file) in this task.
- **ZYRA PROVEN** — established by the user's own past results or confirmed decisions.
- **HYPOTHESIS** — a testable belief, stated with the test that would settle it.
- **ESTIMATED** — computed from stated assumptions; assumptions must be printed next to the number.
- **UNKNOWN** — missing; never silently filled. Either ask, or proceed with the gap flagged and confidence lowered.

## Verification Gates

- Numbers that drive money decisions come from deterministic calculation (scripts), not mental arithmetic.
- A deliverable is inspected after creation (open it, run its actions, read it back) before handoff.
- Completion reports distinguish: what was verified, what was assumed, what remains unknown.
- If verification fails and cannot be fixed, report the failure plainly — never relabel partial work as complete.
